# Deploying

Production layout, all on free tiers: **portfolio-api** on Render (Docker, Singapore), Postgres on Neon (Singapore), **portfolio-web** on Vercel, images on Cloudflare R2. The API runs migrations on boot, so deploying is just shipping the image.

Public names used below (adjust if Render or Vercel gives you a different one):

- **API**: `https://portfolio-api-89p5.onrender.com` (Render adds a random suffix when the name is taken)
- **Web**: `https://<web-project>.vercel.app`, or your own domain later

Free-tier trade-offs: the Render service sleeps after ~15 minutes without traffic and takes ~30–60 s to wake; Neon suspends idle compute and wakes in about a second. Public pages are served from Vercel's ISR cache, so visitors rarely notice; the first admin request after a quiet period is slow.

## 1. Neon (Postgres)

1. Sign up at neon.tech and create a project: Postgres 17, region **AWS Asia Pacific (Singapore)**, database name `portfolio`.
2. Dashboard → **Connect** → turn **Connection pooling off** and copy the connection string (host without `-pooler`). Migrations take a session-level advisory lock, which a transaction pooler doesn't keep. The string ends in `?sslmode=require&channel_binding=require`; keep both. This is `DATABASE_URL`.

## 2. Cloudflare R2 (images)

1. Cloudflare dashboard → R2 → **Create bucket** `portfolio-images` (location hint Asia-Pacific).
2. Bucket → Settings → **Public access**: enable the `r2.dev` URL (rate-limited, fine to start) or connect a custom domain on Cloudflare later. This is `R2_PUBLIC_BASE_URL`.
3. R2 → **Manage API tokens** → **Object Read & Write**, scoped to this bucket only. Copy the Access Key ID, Secret Access Key (shown once) and the endpoint `https://<account-id>.r2.cloudflarestorage.com`.

## 3. Generate secrets locally

Admin password hash (prompted, no echo):

```bash
go run ./cmd/hashpassword
```

Revalidation secret, shared by the API and Vercel. Keep a copy:

```bash
openssl rand -hex 32
```

`JWT_SECRET` is generated by Render (`generateValue` in `render.yaml`).

## 4. Render (API)

1. Sign up at render.com with GitHub and allow access to `maulanaiskak/portfolio-api`.
2. **New → Blueprint** → select `portfolio-api`. Render reads `render.yaml` and asks for every `sync: false` value:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Neon direct connection string |
| `ADMIN_EMAIL` | your admin login email |
| `ADMIN_PASSWORD_BCRYPT_HASH` | output of `hashpassword` (paste as-is, no quotes) |
| `CORS_ORIGIN` | `https://<web-project>.vercel.app` |
| `WEB_REVALIDATE_URL` | `https://<web-project>.vercel.app/api/revalidate` |
| `REVALIDATE_SECRET` | the `openssl rand -hex 32` value |
| `R2_ENDPOINT` | `https://<account-id>.r2.cloudflarestorage.com` |
| `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | from the R2 token |
| `R2_PUBLIC_BASE_URL` | `https://pub-….r2.dev` |

   If you create the service as a plain **Web Service** instead (Docker, region Singapore, plan Free, health check `/healthz`), the fixed values in `render.yaml` are not applied; add them yourself: `APP_ENV=production`, `STORAGE_DRIVER=r2`, `R2_BUCKET`, `TRUST_PROXY=true`, `CLIENT_IP_HEADER=CF-Connecting-IP`, `DB_MAX_CONNS=5`, and `JWT_SECRET` (`openssl rand -base64 48`). The boot log must say `"env":"production"`.
3. **Apply**. The first build takes a few minutes. Check it:

```bash
curl https://portfolio-api-89p5.onrender.com/healthz
```

Seed the CV through the admin API (prompts for the admin password; replaces any stored CV):

```bash
scripts/seed-remote.sh https://portfolio-api-89p5.onrender.com you@example.com
```

### Deploys

Render deploys every push to `main` once the GitHub CI checks pass (`autoDeployTrigger: checksPass`). Manual redeploys and logs are in the service's dashboard. Changing an environment variable in the dashboard restarts the service.

### Rotating credentials

- **Admin password**: generate a new hash and replace `ADMIN_PASSWORD_BCRYPT_HASH`. The restart updates the row and invalidates every existing session token.
- **JWT secret**: Environment → `JWT_SECRET` → Generate. Logs everyone out.
- **R2 keys**: create a new token, update both variables, then delete the old token in Cloudflare.
- **Database password**: reset it in Neon, then update `DATABASE_URL`.

## 5. Vercel (web)

Import `maulanaiskak/portfolio-web` at vercel.com/new (framework Next.js, defaults are fine) and set, for Production and Preview:

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | `https://portfolio-api-89p5.onrender.com` |
| `NEXT_PUBLIC_IMAGE_ORIGINS` | same as `R2_PUBLIC_BASE_URL` |
| `NEXT_PUBLIC_SITE_URL` | `https://<web-project>.vercel.app` |
| `REVALIDATE_SECRET` | same as the API (mark **Sensitive**) |
| `NEXT_PUBLIC_FORMSPREE_ID` | optional, enables the contact form |

If the Vercel URL differs from what you entered for `CORS_ORIGIN` / `WEB_REVALIDATE_URL`, update those on Render. When you add a custom domain later, update both plus `NEXT_PUBLIC_SITE_URL`, then redeploy the web app.

## 6. Smoke test after cutover

- The web URL renders the CV from the API.
- `/admin` → sign in → create a draft post → it is **not** visible at `/blog`.
- Publish it → visible at `/blog` within seconds.
- Upload a photo to a trip → it is served from `R2_PUBLIC_BASE_URL`.
- Delete the test content.
